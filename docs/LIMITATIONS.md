# Limitations

SemiDebug is a research and portfolio CLI prototype for small RTL repairs. Its acceptance rule is conservative but finite: a patch passes the configured simulation, lint, synthesis sanity, hidden regression and integrity gates. These checks do not prove equivalence over all inputs, perform physical verification or establish silicon readiness. Yosys's built-in SystemVerilog support is limited, and unsupported external cases must be counted separately rather than silently removed.

The internal 30-case corpus comes from six original design families. Its six-case holdout uses different mutations of those same designs, so it does not measure generalization to unrelated projects. V1 target and regression shared a testbench source visible to the model. V2 changed this protocol by separating evaluator-only regression sources; V1 and V2 measurements should not be treated as directly controlled model improvements.

The ChipBench sample was selected before model execution and all 12 cases remained in the denominator. It is a small, zero-shot subset. “External” means outside SemiDebug's self-authored fixtures; it does not establish that the model never saw ChipBench material in pretraining. Five of 12 external cases passed, with seven final failures. The model frequently produced invalid unified diffs, and the 40-line patch guard can reject a repair that may be functionally sound. Detailed official test failures are withheld from retry prompts to protect evaluator answers; this limits the feedback available to the model.

Internal one-shot and full-loop conditions used the same model, effort, corpus and tools but were separate stochastic executions. The paired first-proposal versus final comparison within each full-loop trajectory is the stronger measure of what retries rescued. In the internal corpus all seven rescues were format repairs; three external cases had actual semantic retry success. No claim is made that the loop generally improves semantic repair accuracy beyond these observed cases.

The host Codex CLI uses ChatGPT subscription authentication. Token usage and local end-to-end time are recorded, but subscription charges are not converted to API dollars. The API provider path has mocked HTTP tests, not a separately measured live API benchmark. Native EDA execution is for trusted HDL; Docker isolation and patch checks reduce risk but are not a general sandbox for malicious HDL. HWE-bench was not executed, and no result is attributed to it.
