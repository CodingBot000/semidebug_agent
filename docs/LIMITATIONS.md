# Limitations

SemiDebug is an OpenAI API research and portfolio prototype for small RTL repairs. Its acceptance rule is conservative but finite: a patch passes the configured simulation, lint, synthesis sanity, hidden regression and integrity gates. These checks do not prove equivalence over all inputs, perform physical verification or establish silicon readiness. Yosys's built-in SystemVerilog support is limited, and unsupported external cases must be counted separately rather than silently removed.

The internal 30-case corpus comes from six original design families. Its six-case holdout uses different mutations of those same designs, so it does not measure generalization to unrelated projects. The final protocol separates evaluator-only regression sources from the target source visible to the model.

The ChipBench sample was selected before model execution and all 12 cases remained in the denominator. It is a small, zero-shot subset. “External” means outside SemiDebug's self-authored fixtures; it does not establish that the model never saw ChipBench material in pretraining. Six of 12 external cases passed, with six final failures. The model frequently produced invalid unified diffs, and the 40-line patch guard can reject a repair that may be functionally sound. Detailed official test failures are withheld from retry prompts to protect evaluator answers; this limits the feedback available to the model.

Internal one-shot and full-loop conditions used the same model, effort, corpus and tools but were separate stochastic executions. The paired first-proposal versus final comparison within each full-loop trajectory is the stronger measure of what retries rescued. In the internal corpus all seven rescues were format repairs; three external cases had actual semantic retry success. No claim is made that the loop generally improves semantic repair accuracy beyond these observed cases.

The final measurements use the OpenAI API with `gpt-6-sol / low`. Token usage, cached tokens, estimated API cost and local end-to-end time are recorded, but actual invoice totals can differ because account, regional and processing settings are outside the result files. Native EDA execution is for trusted HDL; Docker isolation and patch checks reduce risk but are not a general sandbox for malicious HDL. HWE-bench was not executed, and no result is attributed to it.
